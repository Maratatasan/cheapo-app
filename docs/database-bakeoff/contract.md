# Cheapo database bake-off, contract v1

Read fixture.json. Field names in the fixture specify the wire-level comparison projection. Each implementation may choose native storage, repository API, and setup. Expose one documented command to load the exact fixture into an isolated local database and run the scenarios. Keep feature logic in the repository; avoid filtering/sorting a complete database dump in the test harness. Include the database access path, any reads/writes done by the application, and the commands to reproduce the run.

- Households have independent saved-shop links with private nicknames. List only links for the requested household. Rename and unlink only affect that household. Shared shop, observations and another household’s links survive unlink. A reissued unlink is harmless. Observations are shop/product data and have no nickname.
- Shops, products, households and observations have supplied UUIDs. Exact product identity is independent of comparison group. Barcode is optional, is stored and looked up as text, and is unique when present. Missing barcode lookup returns no product. Retry an identical create with the same UUID and payload without adding a second product or observation. A different payload at an already used UUID conflicts; competing product creates with different UUIDs for the same barcode produce one product and a conflict. Two observations of the same product and shop with different IDs are allowed even at the same timestamp. Use real concurrent calls, not sequential simulations.
- A price observation refers to an existing exact product and shop. Price is a GBP integer in minor units, observation timestamp is UTC ISO 8601, and photoRef is an optional opaque string. It has no image storage or upload behavior. Correction changes price and/or photo reference in place using observation ID and preserves other observations and original observedAt. Reapplying the same correction is harmless.
- Latest price for exact product/shop is greatest observedAt, then lexicographically greatest lowercase observation UUID on a timestamp tie. Return no result if pair has no observations. A historical observation added late does not become current.
- Compare with a reference product ID and household ID. Candidates share comparisonGroup and have observations at a shop currently saved by that household. sameBrand and sameVariety are independent opt-in exact-value filters relative to the reference product. Retain the latest observation per exact product/shop pair. Exclude incompatible dimensions and unknown units, even if they share comparisonGroup. Supported comparable unit families for this POC are g/kg → kg, ml/l → l, and each → each. Normalized minor unit price is priceMinor divided by amount in the normalized unit, using exact price ordering where possible. Comparison has no FX conversion. Order by normalized unit price ascending, then shop UUID ascending, then product UUID ascending. Report productId, shopId, observationId, unit, and normalizedPriceMinor. The fixture results have exact integer normalized prices.
- The fixed scenarios in fixture.json run in order after an initial seed. Use separate fresh fixture loading for performance experiments. Assert the projection and ordering, using any test adapter to translate API naming and return types. Record actual query plans or consumed capacity where available. Baseline is local and functional. Any optional timings are local observations and require command, environment, sample size, cache conditions, and caveats. No cloud resources, deployment, app wiring, auth, or mobile verification are in scope.

## Assessment rubric

A missing actual database run or failed common scenario blocks a full correctness pass. Score remaining evidence from 0–4 per criterion (0 absent, 1 weak, 2 adequate with material gaps, 3 strong, 4 compelling in this scope). Weight correctness and concurrency 30%, data access and write behavior 20%, schema evolution and product fit 20%, operability and cost assumptions 15%, reproducibility and maintainability 15%. Assess rice plus future categories, history, household sharing, and geography. Treat extrapolations and unverified cloud/security/performance characteristics as gaps, and recommend for Cheapo rather than for databases in general.
